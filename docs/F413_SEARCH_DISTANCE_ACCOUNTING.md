# F413 探索中の処理遅延による距離累積の修正

2026-09-23。mini_r2 / mini_r3 共通。実機走行・書込みは未実施。

## 原因と mini_r1 の既存対策

F405 の `search.c:conf_route()` は、進路判断前後の `real_distance` の差を
`g_search_coast_mm` に保存する。`drive.c:consume_search_coast_mm()` が次の
直進、90度ターン入口、半区画減速停止の距離からその分を差し引く。
mini_r1 には既に処理中の移動距離への対策がある。

F413 の探索は区間ごとに `現在距離 + 指定距離` を停止・通過目標にしていたため、
壁読取り、経路判断、イベント記録中の移動と終点検出の遅れを毎回上乗せしていた。
F413 の最短走行には予定終点を引き継ぐ仕組みがあるが、探索にはなかった。

## 修正

`f413_search_step.c` で連続走行の予定終点を保持する。

```
次の予定終点 = 前の予定終点 + 区間の公称距離
今回の指令距離 = 次の予定終点 - 現在の実距離
```

- 直進、90度ターン入口/出口、壁切れ待ち、最終減速停止に適用する。
- 加速度から出口速度を求める場合も残距離を使用する。
- 壁切れ検出時は、イベント書込み前の実距離を基準に取り直す。
  その後の壁切れオフセットからも書込み中の移動を差し引く。
- 前壁による入口補正、前壁への停止引継ぎ、壁合わせの完了は物理補正として基準を更新する。
  前壁距離の判定値は公称の入口距離から求め、処理遅延で変えない。
- ターンコア/超信地旋回後は実距離へ基準を更新し、意図した旋回中の移動を次区間から引かない。
- 後退、探索フェーズ再発進、セッション開始時の距離リセットは基準も同時に初期化する。
- 処理遅延で次の区間全体を通り過ぎた場合は停止してTIMEOUTとする。
  その場からもう1区間を追加したり、通過済みの入口からターンを開始したりしない。

制御ゲイン、停止の許容誤差、タイムアウト時間、ログ形式、NVM配置は変更しない。
F405 / mini_r1 の既存処理と最短走行も変更しない。

## 検証と実機での確認点

`sh tools/hil/run_f413_search_distance_tests.sh` は実際の探索関数を呼び、
理想追従の1 msモデルと処理待ち0/3/8/20 msで7/15/60区画を連続実行する。
両profileで最終目標が公称値を維持し、7区画では730 mmとなることを検証する。
左右ターン、壁補正の有無/早い検出/遅い検出、壁切れ記録中の移動、
壁合わせ、180度旋回、後退・フェーズ再発進、途中中断後のリセットも対象。

両profileの距離回帰、既存停止/壁合わせ、制御tick・全軸ゲイン選択・速度feedback、
機体registry、runtime goal/BFS/solver試験がPASS。共有solver探索シミュレーション、
route precompute 14210 checks、F413/F405 Debug build、diff checkもPASS。
F413はRAM274264 B / Flash377060 B。生成route表は入力fingerprintのみ更新し数値は不変。
mini_r2 t0.3 / mini_r3 t0.25。ローカルのタイヤ径/ゴール/走行調整値は保持する。

ホスト検証は指令距離と処理順序の確認であり、実機の制動・接地・壁センサ精度は保証しない。
次の同条件の探索で、最終目標が約730 mmとなり、壁接触なく停止できることを確認する。
壁切れ/前壁補正が発生した場合は、その物理基準補正による距離変化を別途評価する。
本作業では UART、ST-LINK、モータ、ファン、実機NVM操作を実行していない。
