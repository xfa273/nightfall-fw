# 最新ランタイムの探索終了証明に関する監査

対象は `3910fa6` の最短経路実装。2026-09-06 にコードとホスト上の局所条件を独立に検査した。結論は、**primary pass の辺集合が非単調という事実だけでは、楽観的な時間下界は否定できない**。以下の条件付き証明は成立する候補がある。ただし、現在の MCU oracle を最新実行モデルへ移植したものではなく、この監査を根拠に最新機体を有効化していない。

## コード上の論点

以下の行番号は同コミットの [f413_route_preview.c](https://github.com/xfa273/nightfall-fw/blob/3910fa6/platform/stm32f413/HM_Nightfall_f413_preorder/Core/Src/f413_route_preview.c) に対するもの。

- 2360 行の `f413_rp_large90_nominal_runup_insufficient` は、対応する大回りの幾何条件と、固定された速度・助走条件を検査する。
- 2477–2485 行の `f413_rp_small_required_for_goal_stop` は、大回りと小回りがともにゴールへ入る場合に、`!large_brake_tail && small_brake_tail` なら小回りを許す。壁の追加で大回りの停止が不能になり、小回りの候補が増えることは実際にある。
- 2567 行・2611–2617 行は、助走不足または上記の停止条件で小回りを採用する primary pass の入口。
- 2298–2347 行では、ゴールに入る旋回は終端候補となり、通常の次状態へ遷移しない。壁の追加によって新しく許される上述の小回りも終端である。
- 2812–2825 行の `f413_rp_plan_execution` は、primary pass に実行可能な終端がない場合だけ recovery pass を実行する。recovery の候補を primary と常時競争させるモデルとは異なる。

## 条件付き証明の候補

未知辺を通路とする地図を O、既知情報と矛盾しない完成地図を T とする。

1. 最新 **primary pass 全体**を O で解いた値を L とする。助走不足とゴール停止の局所 small90 を残し、全体の recovery pass だけを除く。small90 をすべて除いたグラフの値は、そのまま下界には使えない。
2. 既知の通路だけで実行できる nominal の primary 経路を別途検証し、そのゴール進入時間を U とする。旋回の幾何ガード、速度遷移、初期動作、停止尾部、実ランナーの preflight を含める。その経路がすべての T で残るなら、T に primary の終端が存在するため recovery は起動しない。
3. primary の通常の辺は壁の追加で失われることがある。新しく許されるゴール停止用 small90 は、同じ直前状態から出る対応する nominal large90 が O では停止可能だった場合である。もし常に「その large90 のゴール進入時間 ≤ small90 のゴール進入時間」なら、新しい終端候補も O のより安い候補で置き換えられる。
4. この局所的な時間優越が保証できれば、`L ≤ 最新ランナーが T で選ぶ最短時間 ≤ U` が得られる。`L = U` は条件付きの最適性証明となる。

これは辺集合の包含関係を使う証明ではなく、新たな終端候補を既存の候補で置き換える証明である。楽観経路の走行辺がすべて既知という確認だけで、上記 U の独立した検証を省略してはいけない。小回りの採用には、実際に走る軌跡以外の「対応する大回り」の幾何条件も関与する。

## 有限ケースの数値確認

実際の production の static 関数と `f413_route_motion_table.c` を、既存の `f413_route_preview_host_tests.c` と同じホスト環境に取り込んで検査した。これら 3 ファイルが `3910fa6` と一致することを確認した。

検査範囲は mode2 case6–9、4 方位、左右、3 種類の始点速度、助走 0–62 半区画、状態の中心/壁位置と整合する助走の偶奇。内側の中心 (7,7) を基準に、対応する大回り・小回りの 2×2 区画内に置いた 15 種類のゴール集合を調べ、ゴール進入後/O1 進入後に旋回を開始する不許可ケースを除いた。大回りの停止先に壁を加え、**実際に停止用小回りの採用条件が真になる**ケースだけを比較した。

| profile | 採用条件成立数 | small − large の最小ゴール進入時間 |
|---|---:|---:|
| case6 | 1,936 | 230,247 µs |
| case7 | 2,000 | 153,868 µs |
| case8 | 2,000 | 153,868 µs |
| case9 | 1,936 | 230,247 µs |

合計 **7,872 ケースで時間の逆転は 0 件**。例えば case8、北向き右旋回、nominal 始点、助走 0、ゴール (8,8) では、大回りの進入は 226,713 µs、小回りは 380,581 µs。ゴール東側の壁で大回りの停止を妨げると小回りの辺は増えるが、楽観地図には既にそれより速い大回りの終端があった。

この検査は条件付き証明を支持する局所検査であり、全迷路の検証や一般の速度プロファイルに対する証明ではない。新しい機体・テーブル・旋回形状・ゴール/停止規則に適用する前に、局所時間優越と幾何範囲を再検証する必要がある。既存 MCU oracle と最新コードの初期動作・速度・状態表現の差も、この監査では解消していない。
