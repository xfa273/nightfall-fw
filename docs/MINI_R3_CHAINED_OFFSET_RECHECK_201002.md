## 壁切れが発動しなかった理由

| 指標 | 今回1回目 | 今回2回目 |
| --- | ---: | ---: |
| R180最終保存点→L180開始点の時間 | 12ms | 11ms |
| 同区間のエンコーダ距離差 | 17mm | 16mm |
| 最後に更新され、以後保持された左微分 | -190 | -135 |
| 連続対間の壁切れラッチ | 0 | 0 |

前回の同距離差18/19mmから1/3mm短縮している。ただしコア最終保存点と開始点の差であり、
公称オフセット14mmそのものを高精度に測定した値ではない。累積距離の絶対値も前区間の
誤差を含むため、2回目の旋回開始位置が迷路内で何mm変わったかとは同一視しない。

今回1回目の左ADCはseq2528/2532/2536で567→333→50、左微分は0→-41→-132。
seq2540にはgate OFF、最後の左微分は-190で保持される。
2回目はseq2524/2528/2532で422→244→41、seq2528/2532の微分は-9→-62、
seq2536にはgate OFF、最後は-135で保持される。gate ON中も、終端値も、
条件「微分<-200を異なる2更新で確認」を満たさない。
slow項目は4レコードごとの実保存であり、間の保持行を新しいセンサ更新として数えない。

原因として重要なのは、**前後オフセット境界では初期化しなくなったが、旋回終了後の
統合区間入口では依然として微分履歴を初期化している**こと。
`f413_path_run_drive_chained_offsets()`が`f413_wall_runtime_end_clear()`を呼び、
最初のpollで36要素をその時点のADC値で埋める。旋回中のpath処理はこの微分を更新しない。
立ち下がりの途中の値を初期値として約14mm/1400mm/s=10msしか蓄積できず、
今回の波形では閾値と2更新確認に間に合っていない。High/Lowは100/1の補助判定であり、
ADC40〜50ではLowを下回らない。検出がないので`dist_wall_end=-23`も作用しない。

## 次の修正候補と再生確認

全ターンの統合区間は維持し、次は微分履歴の準備時期を修正する。

1. 次が連続ターンの場合、前ターンの旋回終盤だけで微分履歴を準備する。
2. 補正は統合オフセット区間だけ許可し、入口では履歴を残して検出状態を切り替える。
   古い検出ラッチや旋回中の判定をそのまま次のターンへ持ち込まない。
3. 同じ本番判定を保存波形で再生し、短い区間でも新しい更新で検出することと、
   旋回由来の別の立ち下がりを拾わないことを検証する。

今回の本番`f413_wall_runtime.c`をhost共有libraryとしてコンパイルし、実保存された
4ms ADCを線形補間して2ms周期で入力した。これは補間を含む仮想再生で、実測検出時刻ではない。
旋回終了周辺の初期化位相を0/1/2msずらした3条件では、現方式は両走行とも未検出。
位相1msの最終微分-196/-136は実保存-190/-135に近い。
同じ式・閾値で20ms前からgate OFFで履歴を準備すると、今回1回目は従来のL180開始より
3〜4ms前、2回目は4〜5ms前で検出した（おおむね4〜7mm相当）。
40ms以上を無制限に引き継ぐと区間入口付近ですぐ検出する例があり、旋回中の光学変化を
混ぜる問題がある。したがって「常時監視して履歴を全て残す」だけの修正は避ける。
20msは実装済み/確定値ではなく候補。短いターン、左右/斜め、誤検出、実sample位相を含めた
検証が必要で、今回の再生だけで接触回避を保証しない。
