# 探索シミュレータで確認した現状アルゴリズムの特徴（2026-08-30）

ツール: `tools/exploration_sim`（使い方同上ディレクトリの README.md）
迷路データ: `kerikun11/micromouse-maze-data`（過去大会 80 迷路）を
`~/workspace/micromouse/maze-data` に配置して使う。

## 再現した現状アルゴリズム

`search.c` の `get_wall_info()` / `write_map()` / `make_smap()` / `make_route()` /
`conf_route()` をホスト側に移植した（`--sensing fw --map-write overwrite
--propagate fw --strategy fw --unknown-walls open` が現状同等）。

## シミュレータが出した定量結果

### 1. センタ値の絶対方位変換 `m_temp = (wall_info >> dir) & 0x0f` の欠落

`--selftest` で検査できる。4 方に壁があるセルでの期待値と実効値:

| dir | 期待 (F/R/L 3センサ) | 実際 | 欠落する壁 |
|---|---|---|---|
| 0 (北) | 1101 | 1101 | なし |
| 1 (東) | 1110 | 0110 | **左壁 (N)** |
| 2 (南) | 0111 | 0011 | **左壁 (E)** |
| 3 (西) | 1011 | 0001 | **左壁 (S) と 右壁 (N)** |

`wall_info` は F=bit3 / R=bit2 / B=bit1(未使用) / L=bit0 の相対ビットなので、
右ローテートすると下位ビットが流れ出て、**左壁（東西南北のうち進行方向左）が
常に読めない**。後方センサが無いのと合わさると、左折先の壁が常に「なし」になる。

### 2. その結果、地図が自我破壊する（`write_map` の現マス上書きと複合）

`map[y][x] = m_temp` の上書きなので、**観測できない方位の壁は消える**。
`--propagate fw` は「壁なし」も隣へ伝搬するため、隣の正しい壁まで消える。

sensing=`fw_fixed`（回転だけ修正）でも上書きが残るとスタックした:

| 設定 (strategy=fw) | phantom_hits（未知の壁への進入） | 初ゴール |
|---|---|---|
| overwrite（現行） | 45 | 未達 |
| accumulate（OR 蓄積） | **0** | 完走 |

### 3. 探索目標の選び方だけで初ゴール時間が 3 分の 1

センサ・時間モデルを同一条件（`--sensing ideal4_ahead`、全探索優先、5 走）で、
目標選択だけ差し替えた比較（単位: 秒、4 大会の決勝迷路の平均）:

| 目標選択 | 平均 t_first_goal |
|---|---|
| `fw` … 未探索セルを全点 0 とする 1 セルコスト BFS（= 現状の最近傍） | 108.4 |
| `dijkstra` … 同上だが距離場を時間コスト化 | 103.5 |
| `gain` … 「その区画を割った後のゴール所要時間」で目標選択 | **33.1** |

1 セルコスト BFS は旋回数を数えないため、**距離は短いが旋回が多い経路**を好む。
現状のコスト関数（`solver_params.c` の `turn_penalty=0.80` 等）は最速走行側にしか
入っておらず、探索の `make_smap()` は素の歩数 BFS のままになっている。

### 4. 現状同等設定での所要時間目安（参考）

`--sensing ideal4_ahead --strategy fw --goal-policy full_first`（現行の探索順）で
全日本決勝迷路 9 件の平均: 初ゴール 20〜159 秒、累計走行 170〜328 秒、
走行セル 483〜823、旋回 202〜530 回。**旋回数が直進セル数と同オーダー**であり、
探索の旋回コスト最適化が効いていないことを示す。

## 対処の候補（効果順）

1. 観測値の絶対方位変換を正す（`--sensing fw_fixed` に相当）。左壁が読める。
2. `map[y][x] = m_temp` を `map[y][x] |= m_temp` に（不明方位で情報を消さない）。
   伝搬も「壁なし」は既知のときだけ消す、など段階的に。
3. 前方セルの側壁を読むセンサ構成にする（上位機標準）。`--sensing ideal4_ahead`
   で効果測定できる（phantom 0 になる）。
4. `make_smap()` を旋回コスト込み・時間コストの距離場にする。
5. 探索目標を「最近傍」から「ゴール利得最大」に変える。

### 5. ゴール区画でランが止まる影響（小さくない）

ルールどおり「ゴール区画に進入した時点でラン終了」(`--end-run-at-goal always`) と
「探索走行ではゴールをまたいで走り続けられる」仮定を比べた:

| 条件 | 平均 t_first_goal | 平均踏破率 |
|---|---|---|
| always（ルール通り・現行前提） | 107.9 s | 98.9% |
| never（仮定） | 107.9 s | 99.9% |

初ゴール時間は同じで、踏破率が残る 5 迷路で 98.4〜99.2% に頭打ちになる。
「探索 1 本で 100% に届かない」のは目標選択の性質なので、2 本目の設計
（どこから再開するか）を明示すると回収できる。

## 可視化 UI で確認したこと（2026-08-31）

`tools/exploration_sim/viewer.py` で、現状ソフトと改善版を同じ時間軸で並べ再生できる。
生成物: `out/exploration_sim/viewer_<maze>.html`（単一ファイル・外部依存なし）。

### 修正効果の アブレーション（16MM2017CX / 2019CX / 2020CX の 3 迷路平均）

| 設定 | 平均 初ゴール | ゴール到達 | phantom 計 | 平均踏破率 |
|---|---|---|---|---|
| 現状（変換も地図も現状のまま） | 未達 | 0/3 | 27 | 9.9% |
| 回転のみ修正（未観測を「壁なし」として扱うのはそのまま） | 未達 | 0/3 | 27 | 18.6% |
| 地図更新のみ修正（読めない方位を触らない／OR 蓄積） | 106.9 s | 3/3 | 80 | 98.8% |
| **両方修正** | 102.8 s | 3/3 | **0** | 98.8% |
| 両方修正＋ゴール利得目標 | **35.6 s** | 3/3 | 0 | 84.1% |

読み方:

1. **決め手は「読んでいない方位を“壁なし”と扱わない」こと**。変換式を直しても、
   後方センサが無いことを「壁なし」として地図に書き続ける限りスタックは解消しない。
2. 地図更新だけ直すと走れるようにはなるが、 phantom（未知の壁への進入）が 80 回残る。
   変換式も直すと 0 になる。
3. 地図が正しくなることと、初ゴール時間は別問題。目標選択を利得ベースにするだけで
   初ゴールが 102.8 s → 35.6 s（踏破率は 98.8% → 84.1% に下がるので、
   「探索の深さ」との权衡を走行計画で決める必要がある）。

## ラン進行を機体実装に合わせて修正（2026-09-13）

それまでのシミュレータは「ゴール区画に入ったらそのラン終わり、次ランは開始位置から」
としていたため、**ゴール直後に壁を無視して開始位置へ瞬間移動して見える**不具合があった。
実装 (`platform/stm32f405/Core/Src/search.c`) は次のとおり。

| 機体の挙動 | 実装の根拠 |
|---|---|
| 全面探索（`SEARCH_MODE_FULL`）ではゴール到達で**止まらない** | `is_in_goal_cells()` で `MF.FLAG.GOALED=1` と `s_post_goal_active=true` を立てるだけ。`search_end` は付かない |
| ゴール到達後は地図保存の機会を記録する | `track_post_goal_map_update_around_mouse()` / `s_post_goal_save_pending`（`SEARCH_MODE_FULL` ではゴール後最初の停止で保存） |
| 探索終了条件は「未探索セルへ向かう経路が無い」 | `mstep > MAZE_SIZE*MAZE_SIZE-(MAZE_SIZE-1)` で `search_end=true` → `half_sectionD()` + `drive_stop()` |
| ゴールへ走る／スタートへ戻るの切り替え | `SEARCH_MODE_GOAL` 側で `g_goal_is_start` が立っているときはスタート到達を、立っていなければゴール到達を `search_end` にする |

シミュレータ側も同じ流れにした。

- ラン 1 = 全面探索。ゴールを通過しても走り続け、未探索が無くなるまで続ける
- ラン 2 以降 = `SEARCH_MODE_GOAL` 相当。そのランの開始位置がゴール側なら**スタートを
  目的地**、それ以外はゴールを目的地にする（`g_goal_is_start` 相当）
- ランの切れ目は係員が機体を開始位置へ戻す動作として `action='P'` のフレームで表現
  （キャンバスでは機体を非表示にして破線枠と `P` を描画。タイムラインには白線）

### アブレーション再計測（16MM2017CX / 2019CX / 2020CX の 3 迷路平均・`end_run_at_goal=never`）

| 設定 | 平均 初ゴール s | ゴール到達/3 | 平均踏破% | phantom | 壁無視テレポート |
|---|---|---|---|---|---|
| 現状 | 未達 | 0/3 | 9.9% | 27 | 0 |
| 変換のみ修正 | 未達 | 0/3 | 18.6% | 27 | 0 |
| 地図のみ修正 | 106.9 | 3/3 | 99.9% | 74 | 0 |
| 両方修正 | 102.8 | 3/3 | 99.9% | 0 | 0 |
| 両方修正＋利得目標 | **36.2** | 3/3 | 78.7% | 0 | 0 |
| 上位機相当 | 36.2 | 3/3 | 78.6% | 0 | 0 |

注意: ゴールで止まらなくなったので「踏破%」は**その場までに割れた区画率**の意味に
なった。利得目標は初ゴールが速い代わりに奥の区画を割りに行く動機が薄く、
探索打ち切り時点の踏破率が下がる（250 近傍の未踏区域が残る）。
「探索の深さ」と「初ゴール時刻」のトレードオフは、走行計画（何本目を何に使うか）で
決める話になるので、UI の右ペインで `fixed_map` と `fixed_gain` を見較べて判断する。
