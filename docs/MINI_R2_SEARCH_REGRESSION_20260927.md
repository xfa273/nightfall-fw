# mini_r2 探索不調の調査（2026-09-27）

対象: `trace_bin_20260927_134707.raw` と run001/run002 CSV。
ユーザ報告: ターンごとに位置がずれ、センサ異常と思われる途中終了。
直進も振動的に感じる。mini_r3 製作前、少なくとも8月には正常探索できていた。

## 結論と確度

mini_r2 の探索パラメータ配列は7月20日以降不変だが、r3対応期間に
F413共通の探索・制御を変更しており、r2の実動作は不変ではない。
9月23日の距離累積修正と既存の壁切れ補正を組み合わせると、同じ物理的な
壁切れを1つ次の区画のイベントとして扱う条件を、実探索関数の旧版/現行比較で再現した。
今回の2ログの座標差と整合するが、両ログの実行FW SHAと実迷路配置を確定できていないため、
全症状の原因をこの変更だけに断定しない。

直進振動については8月30日の共通IMUレンジ修正が速度フィードバックを変える。
これはr2にも適用される実際の挙動差だが、今回のイベントログでは周期的な振動や
閉ループ安定性を評価できず、原因候補に留める。

## ログから直接確認できること

各56行、mode1 case2（全探索）とcase4（ゴール探索）。
`fw_capture_metadata=not_stored` のため実行時の機体識別/FW SHAは保存されていない。
機体はユーザ報告に基づきmini_r2として扱う。FRAMに複数走行を保持する実装なので、
ダンプ日時が同じでも同じFWで走った証明にはならない。

| 項目 | run001 / case2 | run002 / case4 |
| --- | --- | --- |
| 最初の右壁切れ | seq11、action4、座標(0,4)、距離415 mm | seq13、action5、座標(0,5)、距離424 mm |
| 区間内の検出位置 | 76.130 mm | 6.659 mm |
| 最初の右折判断 | seq13、(0,5)、距離463 mm | seq15、(0,6)、距離471 mm |
| 記録末尾 | (3,5)で`full_unreachable`、その後45 mm停止区間 | (4,6)で左折判断、旋回完了記録なし |
| 記録されたmotion abort | 全件none(0) | 全件none(0) |
| session_end | なし | なし |

両runは最初の右折までの実距離差が8 mmなのに、論理座標が1区画異なる。
右・左・右と進んだ後も、最初の東向き直線はrun001がy=6、run002がy=7になる。
case2/4は探索目標が違うが、同じ標準探索パラメータ・壁補正ONを使う。

run001 seq54の`full_unreachable`は「未探索セルに到達する経路がない」という
探索フェーズ終了判定であり、ADC/IMU/encoder faultではない。
seq55の停止区間もstatus=0だが、session_endがないため完全な正常停止は証明できない。
run002も末尾の左折判断以降が記録されておらず、停止理由は不明。
両方56件でheader更新単位8の倍数なので、未確定末尾の欠落も除外できない。

公称90 mm直進のmotion_endだけを抜き出すと、run001は14点で指令300～332、
実速度258～385 mm/s、run002は15点で指令299～331、実速度257～379 mm/s。
速度ばらつきはあるが、数百msごとのイベント値から振動周波数やターン中の軌道誤差は求めない。

## 実関数による距離修正前後の比較

比較対象は`a461d4f^`の`f413_search_step.c`と現行。同じr2探索paramsをリンクし、
既存`f413_search_distance_tests.c`の理想1 ms追従モデルを使った。
入口後9 ms、区間間6 msの処理待ちを与え、壁切れを距離415または424 mmに固定。
実ADC波形や実機の摩擦を再現する試験ではなく、同じ検出位置での区画帰属を比較する試験。

| 固定壁切れ位置 | 距離修正前 | 現行 |
| --- | --- | --- |
| 415 mm | y=4区間で検出、約460.296 mmで完了、次はy=5 | y=4区間で検出、約460.328 mmで完了、次はy=5 |
| 424 mm | y=4区間で検出、約469.251 mmで完了、次はy=5 | y=4区間を415.255 mmで完了。y=5区間で検出し約469.276 mmで完了、次はy=6 |

現行は公称55+90*nの終点を保持するため、y=4区間の終点が415 mmになる。
その直後の壁切れは次区間へ入り、既存処理が「検出位置+45 mm」を次の終点にする。
区画更新側はどちらの場合も1区画進んだと扱う。この組合せが座標差を作る。
旧版は処理中の移動距離を毎回上乗せしていたので、同じ424 mmの壁切れまで前区間で待つ。

したがって距離累積修正はr2の壁観測・区画更新にも影響する。単に距離累積を戻せば
直るとは限らず、前壁への累積過進入を再導入する。壁切れの採用区間と補正後の
観測位置を、実迷路の座標基準と合わせて検証する必要がある。

元の距離回帰試験は今回も両profileでPASS。単区間の壁切れ・イベント書込み中移動と
壁なし連続区間は扱っているが、同じ物理壁切れが区画境界をまたいだ場合の座標帰属を
保証していなかった。ビルド/理想追従の合格だけではこの相互作用を検出できていない。

ローカル再現物: `build/search_regression_20260927/` の `search_before.c`、
`probe_before.c`、`probe_current.c`、各実行ファイル、`before.txt`、`current.txt`。
旧/現行ともAddressSanitizer/UndefinedBehaviorSanitizer付きで実行した。

## 8月の状態からr2にも入った主な共通変更

| 変更 | r2への影響と今回の評価 |
| --- | --- |
| `8265908` / 8月30日 IMU加速度レンジ | r3立上げで見つかった±8g設定/±16g換算の不整合を、共通初期化で0x7C→0x74へ修正。換算係数0.488は維持するため、同じ物理加速度の値が従来の約半分になる。r2は30 ms窓の加速度補助速度を直進の制御に使うので、ゲイン不変でも速度ループ入力は変わる。直進振動の候補。 |
| `a3d2dcf` / 9月6日 機体profile選択 | r2の極性、encoder符号/CPR、PWM、IMU軸は旧設定を保持。現行machine host試験でr2/r3個体選択とパラメータコピーを確認。実機の識別値は今回未読。 |
| `a99db92` / 9月6日 r3 IMU取付補正 | r2は軸符号+1、位置offset=0なので遠心加速度補正は無効。r3の反転/後方2.5 mm補正がr2に混入する実装ではない。 |
| `665cb21` / 9月21日 停止・速度profile修正 | 減速終端・距離保持・到達後の加速度FF除去を共通変更。前壁合わせへの移行や停止を変えるため、r2にも実機確認が必要。通常の定速直線を直接説明する根拠は不足。 |
| `349dea2` / 9月21日 固定上限撤去 | 速度推定±1200 mm/s制限などを撤去。今回の300～332 mm/s走行でこの上限撤去が主因という根拠はない。 |
| `a461d4f` / 9月23日 探索距離累積修正 | 上記の区画帰属差を再現。r2/r3共通で適用。 |

8月29日のターンコア定速化・旋回中encoder LPF化は、r3立上げ前のr2動画/走行で
調整した履歴がある。ユーザの「8月中」の正常探索日が未特定なので厳密な良好版は確定しないが、
r3専用変更として扱わない。

9月26～27日のr3 mode3/4最短壁切れ値（-15/-23 mm）はr3の最短profileの値。
r2探索の45 mm、High200/Low100、速度300 mm/s、alpha10200、in8/out12.8 mmは変わっていない。
r3吸引ゲインもfanのないr2探索では選ばれない。

- 現行の探索配列、共通制御、IMU初期化、機体registry、壁センサ/壁切れ処理の履歴を確認。

次の切り分けは、実行FW/機体profileと8月の良好版を固定した比較、同じ迷路での
最初の壁切れ/右折の座標確認、直進からターン入口・出口までの連続制御ログ。
イベントだけのログでは直進振動や毎ターンの位置ずれを同定しきれない。
原因未確定のままr2のゲインや壁切れ距離を合わせ直すことはしない。

本調査はホスト解析のみ。firmware/params変更、build/flash、UART、ST-LINK、
モータ、ファン、実機NVM操作なし。他作業の未コミット変更は保持。
