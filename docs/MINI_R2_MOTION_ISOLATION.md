# mini_r2 の走行復旧と r3 変更の明示的な選択

2026-09-27。ユーザの「r3の変更がr2へ不意に波及しないようにし、以前の走行へ戻す」依頼に対応。
原因調査は [MINI_R2_SEARCH_REGRESSION_20260927.md](MINI_R2_SEARCH_REGRESSION_20260927.md)。

## 復旧の基準と実装

r2はr3立上げ直前の **57a9c3b（2026-08-29）** の走行処理を基準にした。
8月29日の旋回定速化・旋回中encoder LPF化はr2で調整した履歴があるため維持する。
ユーザの良好走行の正確な日付／FWは未確定であり、このcommitを実機で良好確認済みと断定しない。
r3は本修正前の **8edeea0** の動作を維持する。

`F413_MOTION_FEATURES` をprofileのscalarとして追加し、同じF413 binaryでも
boot時のidentityで選んだ機体のpolicyを読む。r2は0、r3は以下8項目を列挙してopt-inする。
UARTやNVMから変更する設定ではない。未知bit、および停止処理なしの前壁復帰指定は起動拒否。
起動ログは `[MOTION] baseline=57a9c3b opt_in=0x00000000`（r2）、`0x000000FF`（r3）。

- r2のIMU初期化／診断を0x7Cへ戻す。換算係数0.488との歴史的な不整合も含め、旧制御入力を再現する。
- r2の速度profile終端、加速度FF、停止待ち、前壁合わせ／後退復帰、探索区間距離を8月方式へ戻す。
  前壁処理は `f413_search_front_aug29.inc` に出典付きで固定し、入口で明示選択する。
- r2の推定速度±1200、直線1500・斜め1000・旋回500 mm/s、角速度2200 deg/sの旧上限、
  tuning時角度ゲイン4/0/0、case0固定45 mm停止を復元する。
- case0のアプローチ速度制限とR180助走延長をr3だけにする。
  mode7旧配列のR180はsub7であり、r3吸引配列のsub2とは異なる。
- **r2 mode2 case6は、8月の壁補正OFF・固定斜め検証経路へ戻る。保存迷路最短ではない。**
  経路は `203,701,1001,802,1001,703,202`。case7..9の保存迷路方式は維持する。

機体identity・配線極性・個体識別、NVM保護、ログ保持／取得、機体別params/goal/LUT参照は維持する。
これらを旧版へ戻すとr3や保存データの扱いを壊すため、走行処理だけを選択する。
F405のコードとprofileは変更しない。作業前からあるr2最短case3/4の加速度など、
ユーザによる調整値も上書きしない。8月との比較は**同じ現在の機体paramsで処理を比較**したもの。

## r2への再導入候補（今回は全て未適用）

| 項目／bit名のF413_MOTION_以下 | r2へ取り込む判断 | 取り込む前の確認 |
| --- | --- | --- |
| `IMU_16G` | 優先候補。物理量のレンジ／換算整合は修正すべき。ただし既存制御が旧スケールで調整されているため単独切替で走行同等にはならない | 既知加速度・encoderとの比較、加速度補助速度、直進の連続ログで旧版比較。ゲイン／補助重みの再評価 |
| `SETTLED_STOP` | 優先候補。減速終端で加速度FFを残さず距離積算を止める変更と停止待ちを一組で評価 | 壁なし停止、前壁接近、後退、再発進、timeout／接触の有無。固定機だけでは合格にしない |
| `FRONT_RECOVERY` | 有用な候補。過接近時の後退とセンサ範囲外からの復帰。`SETTLED_STOP`に依存 | r2の7 mm前壁基準・LUTで、近すぎる／片側だけ有効／通常位置を確認。r3の45 mm基準を流用しない |
| `SEARCH_DISTANCE` | 保留。処理時間中の過走行を抑える方向は妥当だが、今回の区画帰属ずれを再現した | 壁切れが公称区間境界の前後にある迷路で、物理壁・区画更新・補正後観測位置を一緒に検証。単なるbit ONだけで採用しない |
| `PARAMETER_LIMITS` | 保留。固定上限の撤去とパラメータに従う停止距離は合理的だが、r2の高速域・case0停止余白を未評価 | 速度推定の上限、旋回／直線上限、停止尾部を個別に評価。部分採用するならこのbitを分割する |
| `CASE0_TURN_SPEED` | 調整モード用候補。孤立旋回テストの前後速度を旋回速度へ揃える | 通常最短には適用せず、case0各経路の助走距離と速度到達を確認 |
| `CASE0_LONG_R180` | 必要な速度だけ検討。高速r3向け助走延長であり、r2探索の復旧には不要 | テスト経路の占有範囲、停止余白、modeごとのsub配置を確認 |
| `MODE2_CASE6_SAVED_MAZE` | ユーザの操作意図で選択。制御修正ではなくcase6の意味を変える | 固定斜め調整を別の操作へ残すか決め、保存迷路・goal・table整合を確認 |

r3専用のIMU取付符号／後方2.5 mm補正、吸引起動・FAN_ONゲイン、各旋回寸法、
壁切れ-15/-23 mm、前壁距離基準、機体LUTはr2へ転用しない。

今後の機体限定変更はpolicyに独立bitを追加し、対象profileだけへ列挙する。
`KNOWN_FEATURES`や機体番号比較をそのまま有効化maskに使わない。
r2のbitを変更するときはtune version・検証記録を更新し、その意図に対応する互換試験の基準を見直す。

## ホスト検証

`python3 tools/hil/run_f413_motion_compat_tests.py` はgit履歴の実コードを取得してコンパイルし、
同じparams・入力を与えた結果を現在の実コードと完全一致で比較する。ASan/UBSan付き、実機アクセスなし。
参照commitを含むgit履歴が必要。出力は無視対象 `build/hil_host/motion_compat/`。

| 比較対象 | r2 対8月版 | r3 対修正前 |
| --- | ---: | ---: |
| 制御tick（加減速・前後進・旋回・高速・tuning、PWM含む） | 8,400件一致 | 8,400件一致 |
| 探索（遅延、境界前後の壁切れ、左右旋回、前壁合わせ） | 120件一致 | 122件一致 |
| 全6mode×9caseの経路計画（12経路・通常／テスト） | 1,296件一致 | 1,296件一致 |
| mode2..7のcase／case0呼出し先・特徴・経路 | 126件一致 | 126件一致 |

制御fixtureの機械特性入力は比較双方で固定。実機のr2/r3配線・軸・個体profile選択は
別のmachine試験で確認する。理想追従の探索モデルは摩擦・滑り・CPU処理時間そのものを再現しない。

追加確認: machine選択／拒否、161 scalar coverage、停止・前壁／吸引、探索距離opt-in、
パラメータ上限opt-in、mode2 dispatch、path linear、route precompute、F413/F405 Debug build。
既存の新処理試験は明示的なopt-in fixtureへ変更し、既定r2を新処理として誤検証しない。

作業中のr3吸引mode ladder試験は、既存ユーザ調整値が固定加速度期待値と異なるため失敗する。
当該調整値を除いたcommit対象snapshotでは、r3全5吸引modeの各10テスト経路と
各2,444接続、およびr2全5modeの各10旧dispatchがPASS。既存編集を上書きしない。

**実機への書込み・走行確認は未実施。ホスト一致を実走復旧の証明にしない。**
次の実機確認ではbootの機体・tune・policy・FW SHAを保存し、r2の同一迷路で
直進、左右ターン、最初の壁切れと区画座標、前壁停止を旧ログと比較する。
走行操作は機体を浮上固定した確認、または対象の床／迷路走行の明示許可後に行う。
