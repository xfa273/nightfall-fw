# 探索走行シミュレータ

大会迷路を機体が探索し、前・左右の壁を観測して地図を更新する過程を、従来の足立法と経路優先探索で比較するホスト専用ツールです。迷路、機体の探索速度、最短走行用パラメータ、許容差、帰還条件を固定して、探索時間・軌跡・経路確定時刻を確認できます。

所要時間は運動学モデルによる推定値です。実機の計測時間ではありません。このツールからモータ、ファン、UART、ST-LINK、NVMを操作する機能はなく、ファームウェアの探索処理やパラメータを書き換えません。

## 起動

リポジトリのルートで実行します。Python 3とC11対応のホストCコンパイラが必要です。Pythonの外部パッケージやNode.jsのインストールは不要です。

```sh
tools/exploration_sim/run.sh
```

[http://127.0.0.1:8765](http://127.0.0.1:8765) をブラウザで開きます。サーバはループバックアドレスにだけ接続します。終了は起動した端末で `Ctrl+C` です。ポートは `--port 8766` のように変更できます。

初回は最短走行プランナを共有ライブラリとして `build/solver_host/` にコンパイルします。迷路データが見つからない場合は、後述の固定版を `build/exploration_sim/maze-data/` に取得します。必要なコンパイルとデータ取得が済めば、以後はオフラインで使用できます。

### UIでの比較

1. ハーフ／クラシック、年度、ラウンド、迷路を選びます。ハーフには `mini_r2_0`、クラシックには `classic_r1_0` を自動設定します。
2. 探索走行の通常速度、既知区間最高速度、加速度、旋回時間などを設定します。「既定値へ」で現在のファームウェア値へ戻せます。
3. 情報取得の目標にする最短走行プロファイルと許容差を設定し、必要ならスタート帰還を有効にします。
4. 「比較を実行」で両方式を同じ条件から実行します。
5. 再生、1歩送り、スライダーで壁が既知になる順序を確認します。「同じ時間」と「同じ歩数」を切り替えられます。

軌跡・訪問回数・観測目標と、最短走行時間の上下限を表示します。「真の迷路」は表示だけの補助です。この設定を変更しても探索判断には影響しません。最短経路の表示は最終結果であり、観測前の情報を探索側へ戻しません。

「軌跡 CSV」と「実験 JSON」で結果を保存できます。JSONは迷路、実際に使用したパラメータ、全イベント、最終地図、結果指標、データ来歴を含む再現記録です。

保存済みJSONを再計算せずに開くには、`--replay` を使います。

```sh
tools/exploration_sim/run.sh --replay build/exploration_sim/2023-half.json
```

32×32の比較はホスト計算にも数分かかる場合があります。進捗はUIに表示し、ホストの計算時間は機体の推定走行時間へ加算しません。

## 比較するアルゴリズム

### 従来：GOAL → FULL 足立法

mode1 case1の意思決定をモデル化しています。最初に大会迷路のゴールへ足立法で向かい、到達後は未訪問セルすべてを距離0として歩数マップを作り、到達できる未訪問セルがなくなるまで続けます。同じ歩数を減らせる方向が複数ある場合の優先順位は、現在の向きに対して **直進 → 右 → 左 → 後退** です。

未知の境界は歩数計算では通行可能と仮定します。ただし実際に次のセルへ進む辺は、その時点で観測済み・壁なしである必要があります。すべての壁が周辺から判明したセルでも、未訪問なら全面探索の対象です。閉鎖領域の未訪問セルが残っても、到達可能な対象がなくなれば終了します。

元のcase1には探索終了後の自動帰還は含まれません。UIの帰還指定を有効にした場合は、両方式へ同じ帰還処理を追加します。

### 改善：ゴール到達後に経路に必要な情報を優先

最初のゴール到達までは従来と同じ足立法です。まず実際にゴールへ到達する経路を確保した後、次の手順で探索します。

1. 未知の辺を開通と仮定した地図で、指定した最短走行プランナの最速候補を求めます。
2. その候補の実行に必要な辺のうち、未観測のものを抽出します。単なるセル中心線だけでなく、プランナが要求する旋回の通過条件と停止までの条件も含めます。
3. 未観測辺の両端セルを観測候補とし、現在位置からの移動時間と、そこで確認できる関連辺の数で評価します。現在のスコアは `移動時間 ÷ (1 + 0.35 × (関連辺数 − 1))` です。
4. 観測先までの移動計画では、未知区間を通れる可能性も使います。未訪問セルへ入る見積もり時間には1.3倍の係数を掛けます。既知通路だけで遠方の観測先へ向かうと、長い既知経路の往復を繰り返すためです。
5. 実際に実行するのは観測済み開通辺を使う次の1歩だけです。新しい観測を反映して、候補と行き先を再評価します。
6. ゴール到達済みで、後述の経路確定条件を満たした時点で終了します。

帰還は観測済み開通辺だけで計画します。選択した最短走行モデルに実行可能な経路が見つからない場合は、全面探索へフォールバックして原因を確認し、経路確定とは扱いません。歩数上限に達した場合も未完了です。

この探索方針は移動時間と情報取得を両立させるヒューリスティックです。探索時間そのものの最適性や、すべての迷路で従来より短縮できることは保証しません。

## 「経路確定」と上下限の意味

評価対象は、指定した機体・最短mode/caseの**プランナが列挙するモーションの範囲での、スタートからゴール進入までの最短推定時間**です。探索走行の終了時刻とは別の時間です。

- `L`（下限）：未知辺を開通と仮定した地図の最短時間。
- `U`（上限）：観測済みの通路だけで実行できる、これまでに得た経路の時間。
- 確定条件：`U ≤ (1 + ε) × L`。既定の `ε = 0` では上下限一致を要求します。計算上は浮動小数点誤差の許容幅を持ちます。

真の迷路の最短時間を `T*` とすると、このモデル内で `L ≤ T* ≤ U` です。したがって条件を満たせば、取得済みの経路はモデル内の最適解から指定した相対許容差以内にあります。未知壁をすべて知る必要はありません。

下限は、選択済みの楽観経路に必要な辺で新しい壁を観測したときに再計算します。経路外の壁が増えてもその経路の可否と時間は変わらず、他の候補が新たに速くなることもないため、下限を保持できます。上限は有効な既知経路として保持し、新しい辺が32本以上判明した場合などに更新します。表示中の上限はその瞬間の既知地図での最小値とは限りませんが、実行可能な経路の上限です。楽観経路に必要な辺がすべて判明した場合は、その経路を上限にも採用して一致を確認します。

最初のGOAL区間は両方式とも足立法だけで判断するため、計算量を減らす目的で下限の再計算を初回ゴールまで遅らせます。古い値も下限として有効ですが、その時点の楽観地図の最適値とは限りません。無効化された古い候補を使って経路確定を宣言することはありません。

使用するプランナは、リポジトリに取り込んだホスト側の時間最適プランナです。出典リビジョンは結果の `planner_source_commit` に記録します。ハーフはslalomプランナ、クラシックはorthogonalプランナを使用します。クラシックの斜め走行モデルは校正されていません。ハーフの斜め軌道形状にも暫定モデルが含まれます。連続空間や実機の全挙動に対する最適性を示す値ではありません。

真の迷路全体を用いた最短時間は、探索が終わった後の評価用にだけ計算し、`truth_optimum_s` に記録します。探索判断には渡しません。

## 探索速度と時間モデル

探索走行の既定値は `profiles.py` が起動時に現在のソースから読み取ります。主な値は次のとおりです。

| 項目 | ハーフ mini_r2_0 | クラシック classic_r1_0 |
|---|---:|---:|
| パラメータディレクトリ | `params/f413_preorder/` | `params/classic_r1_0/` |
| 区画長 | 90 mm | 180 mm |
| 通常・小回り旋回中の並進速度 | 300 mm/s | 1000 mm/s |
| 既知区間最高速度 | 519.615 mm/s | 1562.050 mm/s |
| 並進加速度 | 1000 mm/s² | 5555.6 mm/s² |
| 既知区間加速度 | 1000 mm/s² | 4000 mm/s² |
| 小回り90度の角加速度 | 10000 deg/s² | 19000 deg/s² |
| 小回り90度の動作時間 | 約0.280808 s | 約0.174488 s |

出典は各ディレクトリの `search_run_params_split.c` の `searchRunParams[0]` と `params.h` です。F413の実行処理は `f413_search_step.c`、F405は `search.c` と `drive.c` を参照しています。mode1 case1の目標切替はそれぞれ `f413_mode1.c` と `mode1.c` にあります。

既知区間最高速度は独立したファームウェア定数ではありません。既知の直進区間で1区画加速し、その後巡航する処理から `sqrt(通常速度² + 2 × 既知区間加速度 × 区画長)` として導出しています。シミュレータでは最高速度を独立に変更できます。

探索時間の計算は両方式で共通です。

- 連続直進では区画間で速度を引き継ぎ、加速・減速可能な速度を前後から計算して三角／台形速度プロファイルの時間を積分します。観測状況に応じて通常速度または既知区間最高速度を上限にします。
- 小回り90度は、ファームウェアの余弦ブレンド角速度プロファイルと、前後オフセット距離を通常速度で走る時間の合計です。UIで角加速度などを変更すると再計算し、`turn90_s` を明示した場合は校正済みの動作全体時間として優先します。
- Uターンは半区画での減速、旋回と待機、半区画の再加速を含みます。`uturn_s` は旋回＋待機だけの値です。F413の実際のUターンは角度PIDの到達判定なので、この値は実測で置き換える前提の推定です。
- 終了時は停止を含めます。任意の `sensor_delay_s` は移動1歩につき加算します。

通常速度の初期値には小回り旋回速度を採用しています。実際のファームウェアは初回に「最初の区間＋半区画」を加速するため、初回巡航はminiで約316.23 mm/s、classicで約1215.64 mm/sになります。また壁合わせ、前壁補正、既知直線の減速バッファにも遷移が存在します。本モデルはこれらを通常速度と共通の加減速モデルへ整理した比較です。

**F405固有のゴール再始動は再現していません。** 実際のclassic mode1 case1はゴール到達で停止し、後退・再加速後、現在向きへ1セル強制前進してから全面探索の次方向を決定します。本ツールは共通の足立法によるGOAL→FULLを連続遷移させます。この差は時間だけでなくゴール直後の探索順にも影響し得ます。Classicの結果は現行ファームウェア全走行シーケンスの逐次再現ではなく、従来の探索方針との比較です。

スリップ、センサ誤判定、ADC周期、制御追従誤差、壁合わせ、NVM保存、操作待ち時間は個別には計算しません。探索アルゴリズムの計算はホスト上で瞬時とみなし、`compute_s` はホストの計算時間として別に記録します。実機の分単位の所要時間と合わせ込む場合は、実測ログから旋回時間や待ち時間を校正してください。

## CLIでの再現と書き出し

```sh
tools/exploration_sim/run.sh --list
tools/exploration_sim/run.sh --maze 32MM2023HX \
  --json build/exploration_sim/2023-half.json \
  --csv build/exploration_sim/2023-half.csv
tools/exploration_sim/run.sh --maze 16MM2014CX --return-home --epsilon 0.01 \
  --json build/exploration_sim/2014-classic-return.json
```

CLIの `--epsilon 0.01` は1%です。UIでは百分率で指定します。帰還なしが既定で、帰還を有効にすると両方式の終了後に同じ処理を追加します。最大歩数は既定12000です。

条件をJSONファイルに保存して再利用できます。例えば次の内容を `build/exploration_sim/config.json` に保存します。

```json
{
  "maze_id": "32MM2023HX",
  "machine": "mini_r2_0",
  "shortest_mode": 2,
  "shortest_case": 8,
  "epsilon": 0.01,
  "return_home": true,
  "max_steps": 12000,
  "profile": {
    "search_speed_mm_s": 300,
    "known_speed_mm_s": 700,
    "acceleration_mm_s2": 1500,
    "dash_acceleration_mm_s2": 1500,
    "turn_alpha_deg_s2": 10000,
    "uturn_s": 0.9,
    "sensor_delay_s": 0.005
  }
}
```

```sh
tools/exploration_sim/run.sh --config build/exploration_sim/config.json \
  --json build/exploration_sim/result.json --csv build/exploration_sim/result.csv
```

省略した設定には現在の既定値を使います。探索プロファイルと、情報取得の目標となる最短走行プロファイルは独立しています。最短側の既定はハーフがmode2 case8、クラシックがmode2 case1です。UIの選択可能範囲はmode2〜5、ハーフcase6〜9、クラシックcase1〜9です。ハーフcase1〜5は斜め直進速度が未定義なので、このslalomモデルでは使用できません。

`profile` では通常速度、既知区間最高速度、2種類の並進加速度、90度旋回の角加速度・丸め係数・前後オフセット・角速度上限・全体時間、Uターン時間、観測待ち時間を変更できます。機体と競技種別の不一致、NaN/無限大、未知の項目、半区画で停止できない速度と加速度の組み合わせは入力エラーにします。半区画停止には `並進加速度 ≥ 通常速度² ÷ 区画長` が必要です。許容差の範囲は0〜50%です。

CSVは各ステップの時刻、座標、向き、観測による変化、既知辺数、訪問セル数、上下限、終了状態を保存します。JSONには使用パラメータと迷路全体も含みます。どちらにもファームウェアのGit SHA/dirty情報とデータの来歴を残します。再計算時はJSONの `profile` と `options` に記録された値を参照してください。

## 大会迷路データ

データは [KeriLabの迷路データ](https://www.kerislab.jp/micromouse-maze-data/) と、その [GitHubリポジトリ](https://github.com/kerikun11/micromouse-maze-data) を使用します。自動取得する版は `762ed2b68735ea29148c6a1251a90ed0651ff26b` に固定しています。MITライセンスの `LICENSE` をデータと一緒に取得します。

既存クローンを利用する場合は、リポジトリまたは `data/` ディレクトリを指定できます。

```sh
tools/exploration_sim/run.sh --maze-dir /path/to/micromouse-maze-data
```

環境変数 `NIGHTFALL_MAZE_DIR` も使用できます。明示指定がなければキャッシュと近隣の既存クローンを探します。既存クローンのpullや変更は行いません。実際に読み込んだデータのリビジョンとファイルSHA-256を結果に記録するので、ローカル版の違いを追跡できます。

`.maze` の `S` と `G` をそのままスタート・ゴールに使用し、中央座標を推測して置き換えません。複数ゴールにも対応します。未確定記号、境界欠損、隣接壁の不整合、未接続ゴールなどは読み込み時に検出します。競技プランナの実行は現在、スタート `(0,0)`・北向き・32×32以下が対象です。

内部座標は `x` が東、`y` が北に増加し、配列は `[y][x]` です。向きは北・東・南・西が0・1・2・3、壁ビットは `1 << 向き` です。ファームウェア由来の逆順ニブルとはアダプタで変換します。

## 検証

```sh
python3 -m unittest discover -s tools/exploration_sim -p 'test_*.py' -v
python3 -m py_compile tools/exploration_sim/*.py
git diff --check
```

小さい迷路の独立したグラフオラクルで、未知の真値を変えても判断が変わらないこと、壁を横断しないこと、観測の対称性、終了と帰還、時間積分、上下限更新、全面探索前の経路確定を検証します。実プランナのテストでは、キャッシュの有無による結果一致と、返した必要辺だけで同じ経路時間を成立させられることを確認します。

実機導入は別の作業です。ここでの探索方針や速度変更はホストシミュレーション内だけに適用されます。

## 大会迷路での比較例（2026-09-05）

探索は上記mode1 case1既定値、最短評価はハーフmode2 case8／クラシックmode2 case1、許容差0%、帰還なしです。秒は四捨五入した推定値です。

| 大会決勝迷路 | 従来・全域探索終了 | 改善・経路確定終了 | 短縮率 | 従来の経路確定時刻 |
|---|---:|---:|---:|---:|
| 2023 ハーフ | 7分35秒 | 5分27秒 | 28.2% | 6分43秒 |
| 2022 ハーフ | 7分14秒 | 3分51秒 | 46.9% | 3分54秒 |
| 2019 ハーフ | 8分37秒 | 6分24秒 | 25.8% | 7分31秒 |
| 2014 クラシック | 1分48秒 | 1分00秒 | 44.5% | 1分22秒 |

いずれも終了時の上下限は全壁既知での最短時間と一致しました（順に18.540092、34.733206、24.679023、20.384636秒）。2022年は早期終了の効果が主で、経路確定に至る時刻自体の改善は約3.3秒です。2023年は経路確定も約76.4秒早まり、終了条件だけでなく観測順序にも効果があります。

追加で2020年クラシック決勝、帰還あり、許容差3%では従来83.030秒→改善54.225秒、両者スタートへ帰還し最短時間8.588268秒で厳密一致しました。許容差10%の別試験では改善46.991秒、取得経路9.244825秒は真の最短8.588268秒より7.645%遅く、指定した10%以内です。

この結果は上記の暫定軌道／理想センサ／時間モデルに対するものです。Classicの再始動差も含め、実走の分単位の予測を求める際にはログによる校正が必要です。テスト済み迷路だけから全大会での優位性は主張しません。
