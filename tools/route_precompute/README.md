# F413 route motion precomputation

`generate.py` evaluates the mode 2 case 6--9 motion model on the host and
generates the const tables consumed by the fixed-memory F413 route planner.
This keeps the expensive trigonometric turn integration out of the MCU.

Regenerate after changing mode 2 turn or case parameters:

```sh
tools/route_precompute/generate.py
```

Check that the committed output is current and numerically identical to a
fresh host calculation:

```sh
tools/route_precompute/run_tests.sh
```

`generate.py --check` compares generated bytes and fails if an input or table
is stale. The generated header also records the SHA-256 of all numeric inputs.

The table contains:

- exact-closure geometry and sampled poses for the seven KERI turns plus the
  small 90-degree fallback;
- three timing-speed variants and integer-microsecond durations for all eight
  turns;
- case-specific orthogonal/diagonal limits and start-offset time; and
- full connector durations for orthogonal/diagonal headings, three entry
  speeds, nominal/low/crawl/stop exit speeds, and 0--68 connector steps.
- wall-end approach durations that use the runner/controller's exact single
  constant-acceleration profile for a lone 45 mm segment, while reserving the
  final 45 mm at turn speed on longer approaches. The lone segment is marked
  infeasible when its required acceleration exceeds either low/high limit
  traversed across the configured switch velocity.
- orthogonal large/small-turn approach durations that reserve the final 45 mm
  at constant turn speed for the runner's wall-end handling.

`UINT32_MAX` marks an infeasible connector. Goal-crossing time within a
connector remains position-dependent and is intentionally evaluated at run
planning time from the already selected linear profile.

The generated linear limits apply the same F413 runner caps (1500 mm/s
orthogonal, 1000 mm/s diagonal, and 500 mm/s turn speed) before calculating
durations, so high raw profile values such as mode 2 case 9 remain consistent
with execution.
