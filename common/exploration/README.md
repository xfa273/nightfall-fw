# 経路情報を優先する探索ポリシー

`exploration_policy.c` は方向を提案するだけの共通 C モジュールです。センサ、HAL、モータ、NVM、真の迷路への参照を持たず、観測済みの壁情報と外部の最短経路計算器だけを使います。F405 の既存探索処理は変更しません。

## アルゴリズム

1. 実際にゴールへ到達するまでは、未知辺を通路とする足立法を使います。現在セルに到達した時点で終了する BFS と、直進・右・左・後退の順の選択を維持します。
2. ゴール到達後、未知辺を通路とした最短時間経路を外部 oracle に計算させます。旋回の幾何条件と停止までの通過辺を含む、経路成立に必要なすべての開放辺を受け取ります。計算中の既定動作は足立法です。実験用の設定では、安価な直交格子 BFS でスタートからゴールへの楽観的な経路を求め、その未知辺を暫定的な観測候補にできます。
3. 必要辺が未知のセルを観測候補にし、方位つき Dijkstra で移動時間を見積もります。未知区間も通路として候補への接近に利用し、未訪問セルへの移動には既定で 1.3 倍のコストを付けます。複数の必要辺を観測できるセルを少し優先します。
4. 全必要辺が既知の通路になり、実際のゴール到達も確認済みなら `COMPLETE` を返します。帰還運動は呼び出し元が既存の安全な走行処理で行います。

この完了判定は、外部 oracle の**有限の経路グラフと時間モデルにおける最適性**を証明します。未知辺を通路としたグラフの最適経路がすべて既知なら、未知壁を追加してもそれより速い経路は生まれず、その最適経路自体も失われません。実機の物理的な大域最適性や、探索時間の最小性を証明するものではありません。外部 oracle が `EXACT` 以外なら証明しません。必要辺の抽出が未完了、計算容量不足、探索予算超過の場合も証明せず、既存足立法へ戻します。

`pending_surrogate` は既定で偽です。有限の計算予算と後述の進捗保持を含む比較では、真にした暫定経路の探索が多くの条件で遅くなったためです。実験用に真にすると、oracle が `PENDING` の間だけ、直交格子経路の未知辺を使って観測へ向かいます。この判断は `reason=SURROGATE`、`lower_us=0`、`certified=false` で区別し、最短時間の下界や完了証明には利用しません。その経路がすべて既知、候補へ接近できない、計算予算が足りない場合は足立法へ戻ります。oracle の計算は継続し、厳密な結果が得られた次のジョブで本来の必要辺へ切り替えます。

探索候補の時間は 5 ms 単位で丸めます。既定値は mini の探索速度に合わせた近似値であり、最短経路 oracle のマイクロ秒単位の目的関数とは別です。探索コストが約 327 秒の表現範囲を超えた場合も、表現できた部分だけで候補を選ばずフォールバックします。

候補の評価値は「移動コスト ÷ 情報量の重み」です。Dijkstra の未確定距離の最小値を、1 セルで観測できる最大 4 辺の重みで割っても既に得た候補より厳密に悪い場合、その先の展開を省略します。同点は展開するため、コスト・座標による tie break は全グラフの計算と一致します。これは探索候補選択だけの枝刈りであり、最短経路 oracle の証明を簡略化しません。

## データと計算の契約

- 配列は `y * width + x`、北が y の正方向、方向は N/E/S/W = 0/1/2/3、ビットは `1 << direction` です。`walls` に未知の真の壁を入れてはいけません。壁は必ず既知ビットの部分集合で、共有辺の観測は両セルで一致させます。
- `generation` は観測の追加で増加させます。同じ `epoch` では既知情報の削除・変更を禁止します。壁判定の訂正、迷路・ゴール・速度プロファイルの変更、世代番号の周回では `epoch` を増加させます。
- 配列は呼び出し元が所有し、`begin` から完了またはキャンセルまで変更しません。観測用の配列とは分けてください。モジュールは観測の単調性と共有辺を検査し、最後にも観測内容を照合しますが、並行書き換えを許可する同期機構ではありません。
- 外部 oracle の結果は計算開始時の epoch/generation を返します。必要辺が現在も通路であり、同じ epoch なら古い世代の最適解を再利用できます。新たに見つかった壁が必要辺に当たれば再計算します。
- oracle の結果には幾何ガード、ゴール進入、停止尾部までの**十分な**開放辺集合が必要です。`dependencies_complete` は、経路全体の抽出が成功して初めて真にします。

## 協調実行と実機への適用

`nf_exploration_decide` はホスト向けの同期ラッパーです。実機の走行境界では呼ばず、`begin` / `step` / `result` を使います。

`begin` は一定量の設定だけを行います。`step(work_budget)` はセル走査、出辺の処理、最大 12 段のヒープ操作を単位として中断できます。構造検査・BFS・Dijkstra・候補選択・最終照合も中断可能です。oracle コールバックだけは外部処理なので、呼び出し元がさらに計算予算と実時間の上限を保証します。処理は IRQ からではなく既存の保護された foreground 待機中に行い、DWT などで全スライスの時間を制限します。

次のセルへ移動開始するとき、観測配列をコピーし、到着予定姿勢で `predictive=true` のジョブを開始できます。未訪問セルへの到着予測でも、未知壁を既知に変えません。未知の出辺を選ぶ場合は `PROPOSAL` を返し、そのまま運動に使えません。到着後に `apply_result` が姿勢・epoch・世代・現在セルの訪問・最初の辺の既知開放を一定量の処理で確認します。条件が合わない、処理が間に合わない場合は既存の足立法を使います。

到着直前の新観測により候補の有用性が変わることはありますが、現在確認された開放辺を 1 セル進む安全性は維持します。予測ジョブでのゴール到着は実到達と扱いません。実際のゴール到達時に `note_goal_reached` を呼んでください。古い世代で成立した完了証明は、同じ epoch の単調な観測追加では失われません。証明に使用した辺はすべて既に既知の通路だからです。

計算の完了が間に合わない到着では、単純に毎セル足立法へ切り替えるだけでは往復が起きます。短い直進では計算が間に合わず、長い旋回では逆向きの改善判断が間に合う場合です。`guard_progress` は候補が間に合わない・採用できない場合に足立法を保持し、実際の観測または新セルへの訪問で generation/epoch が変わるまで、後から完了した移動候補への切り替えを止めます。姿勢変化や予測ジョブの作り直しだけでは解除しません。検証済みの厳密な完了証明は保持中でも採用できます。呼び出し順は `apply_result` → `guard_progress` → 必要なら足立法の候補を設定 → `guard_acceleration` です。

既知区間加速には、前回の運動終了時に次の直進を約束している場合があります。改善ポリシー・足立法・完了判定のどれを選んだ場合でも、最後に `guard_acceleration` を適用します。前回が加速終了で新しい判断が旋回や完了なら、確認済みの直進を 1 セル行いながら減速します。その直進辺が既知の通路でなければ `INVALID` なので、呼び出し元は保護された停止処理で中止しなければなりません。新しい加速約束も、次セルが訪問済みかつさらに先の直進辺が既知開放であることを確認します。

## メモリと検証

動的確保・再帰はありません。ホスト `sizeof` は 32×32 設定で 30,384 bytes、16×16 設定で 7,824 bytes、コンパイル時に 30 KiB 以下を検査します。`NF_EXPLORATION_MAX_SIZE=16` を全 translation unit で統一すれば縮小できます。外部 oracle のワークスペースと呼び出し元のスナップショット配列は別途必要です。

```sh
tools/solver_host/run_exploration_policy_test.sh
```

ホスト試験はゴール到達前の判断、必要辺の証明、古い計算の再利用、訂正時の失効、未完了・予算超過・コスト範囲超過、スライス幅によらない判断一致、途中キャンセル、到着予測の既知情報分離、加速約束を確認します。暫定経路が全既知でも証明しないこと、未知辺を直接走行しないこと、再起動せず厳密 oracle へ切り替わることも検査します。さらに 2,000 通りの再現可能なランダム迷路・速度条件で枝刈りあり/なしを比較し、仕事量以外の判断構造体が一致することを検査します。

`tools/hil/exploration_bench/policy_bench.c` は SRAM 上で DWT を測る独立ベンチマークです。そこで使う oracle は明示した 1 次元の模型なので、実際の最短経路計算器の計算時間は別の planner ベンチマークで測定します。`adapter_bench.c` は実際の F413 アダプタと計算器を組み合わせ、到着時の観測コピー、非同期ポーリング、加速中の完了延期、壁訂正時の停止要求、メモリ貸出の解放を検査します。モータ制御、HAL 実行関数、NVM 書き込みはリンクしません。
